## Rondo

I created **[Rondo](https://workwithrondo.com)**, an open team methodology for building software with AI.

AI assistants now write a large share of the code, yet delivery often doesn't get faster — because writing code was never the bottleneck. Knowing *what* to build is. Without context, AI just guesses faster.

Rondo organizes work around **specification sessions**: people with business, functional and technical knowledge meet, agree on the goal, scope and rules of a change, and write them down. Four roles — owner, functional context expert, technical expert and CDD operator — rotate between teams as the sessions need them, instead of sitting in fixed teams. While one session prepares the next area, CDD operators implement the specifications that are already closed, with AI assistants: the **phase shift**.

It works together with **Context-Driven Development (CDD)**, which keeps four lasting artifacts: `specs/` (what we intend to build), `CHANGELOG` (what was actually built), tests (proof that it works) and `README` (the current state). Every spec has the same nine sections, from TL;DR to control gates and expected outcome. The goal is reproducibility: another AI assistant should be able to rebuild the software from these artifacts alone.

Rondo doesn't replace Scrum or Kanban — it changes how knowledge flows and how teams are composed. Start with the [path for leaders](https://workwithrondo.com/#leaders) or the [cookbook for practitioners](https://workwithrondo.com/#practitioners).
